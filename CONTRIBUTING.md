# Contributing

Thank you for wanting to improve this project. We aim for high-quality, well-documented contributions suitable for legal and press use.

Before you open a PR
- Read the README and PROVENANCE.md to learn the metadata schema for dispatches.
- Run the link checker and any tests locally.
- Run linters (black/flake8 for Python; prettier/eslint for JS if present).

Branching and commit messages
- Create a branch named: improvement/<short-description>
- Use the conventional commit style for messages (e.g., feat:, fix:, chore:, docs:, refactor:).

Pull Request
- Open a PR against the repository default branch.
- In the PR description, include: scope, testing performed, and any compliance notes (legal/press).
- Assign reviewers if known.

Code review expectations
- Keep changes minimal and focused per PR.
- Add tests for logic changes and include examples for data transformations.

Editorial changes
- Do not change substantive factual claims without explicit approval from repository maintainers.
- Minor formatting, citation additions, and metadata fixes are allowed.

Thanks — maintainers will respond within a few business days.
